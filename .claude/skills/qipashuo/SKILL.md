# 奇葩说辩论 Agent 系统

本 skill 指导 Claude 模拟《奇葩说》七位选手 + 马东主持，对一个辩题展开风格鲜明的辩论。每个 Agent 有独立的人物性格 System Prompt，通过 Anthropic API 串行调用，在 React Artifact 中呈现完整辩论过程。

---

| 角色 | 人物 | 风格关键词 | 阵营 |
|------|------|-----------|------|
| 主持人 | 马东 | 幽默、机锋、偶尔毒、煽情收尾 | 中立 |
| 正方1 | 马薇薇 | 毒舌、凌厉、金句密集、不留情面 | 正方 |

| 正方4 | 罗振宇 | 知识密集、框架感强、爱造词、输出焦虑 | 正方 |

## 辩论流程（共 17 步）

```
马东开场宣布辩题
    ↓
正方立论：马薇薇（主攻）
反方立论：陈铭（主攻）
    ↓
马东过渡 → 质询阶段
反方邱晨 质询 正方马薇薇
正方黄执中 质询 反方陈铭
    ↓
马东过渡 → 自由辩论（4轮交替）
罗振宇 → 李诞 → 储殷 → 邱晨
    ↓
马东过渡 → 总结陈词
反方李诞总结（佛系收尾）
正方黄执中总结（催眠式升华）
    ↓
马东最终点评 + 宣布结果
```

### 各阶段字数限制

| 阶段 | 发言方 | 字数 |
|------|--------|------|
| 立论 | 马薇薇 / 陈铭 | 250~350 字 |
| 质询问 | 邱晨 / 黄执中 | 60~80 字 |
| 质询答 | 马薇薇 / 陈铭 | 100~130 字 |
| 自由辩论各轮 | 罗振宇/李诞/储殷/邱晨 | 100~150 字 |
| 总结陈词 | 李诞 / 黄执中 | 180~220 字 |
| 马东点评 | 马东 | 150~200 字 |

## 实现方式：React Artifact + Anthropic API

在 Claude.ai 中创建一个 **React Artifact**，在 Artifact 内通过 Anthropic API 串行驱动各 Agent。

### Step 1：确定辩题

- 用户直接提供辩题 → 使用该辩题
- 用户提供网站 URL → 先用 `web_search` 抓取核心议题，提炼为陈述句辩题
- 辩题格式：陈述句，正反两方都有合理立场（例："年轻人应该接受996"）

### Step 2：构建 React Artifact UI

读取 `/mnt/skills/public/frontend-design/SKILL.md` 获取设计规范。

**UI 组成：**
- 顶部：辩题标题 + 阶段进度胶囊（开场/立论/质询/自由辩论/总结/评判）
- 中央滚动区：发言气泡卡片，每位选手有专属颜色头像缩写圆形
- 底部：当前状态文字（"马薇薇正在磨刀…"）+ 开始按钮

**人物配色（需适配深浅模式，使用 CSS 变量）：**
- 马东：`c-gray`
- 马薇薇：`c-red`
- 黄执中：`c-purple`
- 储殷：`c-amber`
- 罗振宇：`c-pink`
- 陈铭：`c-blue`
- 邱晨：`c-teal`
- 李诞：`c-gray`（低调）

### Step 5：API 调用核心逻辑

```javascript
async function runStep(step, topic, history) {
  const system = SYSTEM_PROMPTS[step.char]
    .replace(/{{TOPIC}}/g, topic)
    .replace(/{{HISTORY}}/g, history || '（辩论刚开始）')
    .replace(/{{TASK}}/g, step.task);

  const res = await fetch('https://api.anthropic.com/v1/messages', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 1000,
      system,
      messages: [{ role: 'user', content: step.task }],
    }),
  });
  const data = await res.json();
  return data.content[0].text;
}

// 每步完成后追加到历史
function appendHistory(history, char, label, text) {
  const name = CHAR_NAMES[char]; // e.g. '马薇薇'
  return history + `\n[${label}] ${name}：${text}`;
}
```

### Step 6：UI 交互行为

- 点击「开始辩论」→ 依次执行 17 步，每步完成后立即追加气泡卡片，自动滚动到最新
- 每张卡片：专属颜色头像圆形 + 姓名 + 角色标签 + 发言内容 + 阶段标签
- 马东的过渡语用浅灰背景卡片区分，视觉上分割各阶段
- 加载中显示个性化等待文案（"马薇薇正在磨刀…" / "黄执中正在沉思……" / "李诞正在躺平…"）
- 最终马东点评卡片字体略大，高亮展示

---

## 注意事项

1. **角色一致性**：每次调用传入完整历史，风格贯穿全程，不能突然变成"正式辩手"
2. **避免重复论点**：history 让后发言的人针对已有内容回应，而不是重复前人观点
3. **全程口语化中文**：贴近节目现场感，禁止书面化表达
4. **字数控制**：system prompt 里的字数限制写清楚，模型容易超长
5. **辩题适配性**：若辩题是纯事实问题，提示用户换一个有争议性的话题
